> 适用仓库：`ros2_quadrotor_sim`  
> 目标环境：Ubuntu 22.04、ROS2 Humble  
> 当前基线日期：2026-07-25
> 使用方法：严格按阶段推进；每项工作和测试完成并留下证据后，将 `[ ]` 改为 `[x]`。

## 1. 使用规则

### 1.1 状态含义

- `[ ]`：尚未完成，或已有实现但尚未按本计划重新验证。
- `[x]`：已完成，并且有代码、日志、截图、测试报告或文档作为证据。
- 历史交接文档中的结果只能作为线索，不能直接将本计划中的测试改为 `[x]`。
- 每个阶段只有在“阶段出口条件”全部满足后，才进入下一阶段。
- 测试失败时保留失败日志，记录根因和修复提交，再重新执行同一测试。

### 1.2 每阶段证据目录

建议将可提交的结果保存到：

```text
docs/evidence/
  phase-00/
  phase-01/
  ...
```

构建临时日志仍放在 `build/`、`install/`、`log/`，不得提交。每阶段至少记录：

- Git 提交哈希；
- 使用的参数文件及其 SHA-256；
- 完整执行命令；
- 操作系统、ROS2 版本和 RMW 实现；
- PASS/FAIL、关键指标和日志路径；
- 若失败，记录根因、修复方式和复测结果。

闭环能够通过目标点验收。

## 阶段 2：动力学模型验证

### 目标

### 工作

- [ ] 明确外部电机输入单位为 RPM，内部推力与反扭矩计算使用 rad/s。
- [ ] 固化 X 型电机顺序：M1 前左、M2 前右、M3 后右、M4 后左。
- [ ] 记录每个电机旋向和 roll/pitch/yaw 力矩符号。
- [ ] 为全部动力学参数增加有限值和物理合法性校验。
- [ ] 明确使用的数值积分方法、时间步长和误差局限。
- [ ] 评估地面约束是否需要接触阻尼、着陆逻辑或仅保留位置钳制。
- [ ] 明确 IMU 输出为理想比力，当前没有噪声、偏置和协方差模型。
- [ ] 决定是否支持仿真时钟 `/clock`；若不支持，在文档中写明使用墙钟。
- [ ] 为路径历史增加可配置上限，避免长时间运行无边界增长。

### 单元测试

- [ ] RPM 为 0 时，四个旋翼推力和力矩均为 0。
- [ ] 四电机相同 RPM 时，roll/pitch/yaw 力矩接近 0。
- [ ] 理论悬停 RPM 与 `sqrt(mg/(4*kF))` 一致。
- [ ] 单独提高 M1 时，roll、pitch、yaw 力矩符号与定义一致。
- [ ] 电机阶跃响应单调接近命令值，时间常数与参数一致。
- [ ] 负 RPM、超上限 RPM、NaN 和 Inf 输入被安全处理。
- [ ] 四元数长时间积分后范数保持接近 1。

- [ ] 欧拉方程中的陀螺项 `omega x (I*omega)` 符号正确。
- [ ] 非法质量、惯量、频率、系数和 RPM 上限使节点明确失败。

- [ ] `/tf` 中存在动态 `map -> base_link`。

- [ ] 输出 CSV/JSON 原始数据，不只保存截图。

### 必做场景测试

- [ ] 悬停：从地面起飞到 `(0, 0, 1.5)`。

- [ ] 最终三维位置误差不大于场景阈值。

- [ ] 无 NaN、状态重置、进程崩溃或 TF 中断。

- [ ] 原始数据和图表可由脚本重新生成。
- [ ] 报告所用数字能追溯到具体运行记录。

## 4. 常用命令基线

```bash
cd ~/ros2_quadrotor_sim
source /opt/ros/humble/setup.bash

colcon build --symlink-install
source install/setup.bash

colcon test
colcon test-result --verbose

ros2 launch drone_bringup sim.launch.py
ros2 launch drone_bringup sim.launch.py rviz:=false
ros2 launch drone_bringup acceptance_test.launch.py
```

在自动验收退出码问题修复前，必须同时检查：

```text
ACCEPTANCE TEST: PASS
acceptance_test_node exit code 0
外层测试命令 exit code 0
```

三项缺一不可。
